# 产品愿景与演进背景

> 记录于 2026-08-18。本文件描述 DSH GUI 的产品演进大背景,供跨项目统筹使用。
> 性质:方向共识,**不是开发计划**;具体任务另行立项,GUI 侧已做的功能登记在
> [FEATURES.md](./FEATURES.md)。

---

## 1. 三个仓库的角色

| 仓库 | 位置 | 角色 |
|---|---|---|
| `ds-harness` | `../../ds-harness` | 上游 DeepSeek Harness 内核,开源,只读(~333 commits/天,不可修改) |
| `dsh-agent-core` | `../dsh-agent-core` | **云端**:自研认证/出口网关 + 文件管理 + 对话插件 + Skills,多用户部署在自有服务器(阿里云 HK,ds.ainativeorg.net),GitHub 私有仓库 ln9527/dsh-agent-core |
| `dsh-gui` | 本仓库 | **桌面**:进程管理器 + 浏览器容器,自包含安装包(macOS/Windows) |

## 2. 收敛方向:一个产品,两个形态

参照 Codex 的产品形态——**云端版与桌面版并存,同一套能力**:

- **云端**(dsh-agent-core)承载:登录与多用户、组织与资源、Skills、
  共享的服务端能力(文件网关、出口代理等)。
- **桌面**(本仓库)逐步继承云端的功能模块:文件管理、对话内引用/下载、
  Skills、助理(assistant)等;同时保持本地自足可用。
- 合并之后,下载安装的 GUI 是一个**全新产品形态**:
  不登录是本地智能体工作台,登录后接入云端账号体系,获得新功能的使用权。

## 3. 登录与组织(未来核心概念)

- GUI 增加**登录验证**:登录后可用云端承载的新功能。
- **组织(org)概念**,账户从属于组织,资源按组织分配:
  - Token 配额、API 资源、数据库资源;
  - 成员列表、成员与成员之间的互动;
  - **人与人通过 Agent 连接、Agent 与 Agent 之间互动**——
    面向未来组织形态的协作方式。

## 4. 记录纪律

- GUI 侧每次新增/变更功能,必须登记进 [FEATURES.md](./FEATURES.md) 一行
  (这是跨项目统筹与版本管理的唯一权威清单)。
- 云端仓库(dsh-agent-core)的功能由那边的工作会话维护;合并规划时两边互查。
- 上游 ds-harness 永远只读;对上游的一切适配走既有的四个适配文件纪律。
