# Apple Developer Program 加入说明(执行手册)

> 记录于 2026-08-23。性质:**交办执行文档**,给具体执行人照做。
> 背景:DSH GUI 的 macOS 自动更新与「无法验证开发者」弹窗,
> 都需要 Apple Developer ID 签名才能解决。详见 [AUTO-UPDATE.md](./AUTO-UPDATE.md) §3。

---

## 0. 这件事要达成什么

拿到一张 **Developer ID Application 证书**,以及配套的公证(notarization)凭据。
有了它,DSH GUI 的 macOS 安装包才能:

1. 支持应用内自动更新(Squirrel.Mac 要求签名可校验);
2. 首次打开不再出现「无法验证开发者」,用户不用再走「右键打开」那一套。

加入 Apple Developer Program 是拿到这张证书的**唯一途径**。

---

## 1. 先决策:账号登记在谁名下(不要跳过这一步)

**这是本文档最重要的一节。**

Apple 的规则:创建 Developer ID 证书**要求 Account Holder(账号持有人)角色**,
且个人(Individual)账号下**只有 Account Holder 能访问证书管理**——
个人账号无法把证书权限分给团队成员。

由此产生一个必须先想清楚的后果:

> **谁用自己的身份完成实名认证,谁就永久拥有这个签名身份。**
> 账号持有人以外的任何人,都无法生成 Developer ID 证书。

所以:

- **不要让学生用自己的身份证和 Apple ID 去注册。** 否则证书归学生所有,
  软件签名显示的是学生的法定姓名,且日后换证书、续费、迁移都必须找他本人。
- 正确做法:**账号持有人 = 老师本人(或公司主体)**。
  实名认证环节(身份证 + 人脸识别 + 付款)必须由账号持有人本人完成,
  这一步无法代劳,代劳即身份冒用。
- 学生可以做的是**除身份认证之外的全部工作**:前期准备、全程操作指引、
  注册后的证书生成与导出、CI 配置、以及后续技术对接。

按这个分工,下面的步骤标注了「谁做」。

### 个人 vs 组织:选哪个

| | 个人 Individual | 组织 Organization |
|---|---|---|
| 需要的材料 | 身份证 + 本人人脸识别 | 公司法律实体 + **D-U-N-S 编码** |
| 审核时长 | 通常 24–48 小时 | 通常 1–2 周,有时更久 |
| 签名显示的名字 | **个人法定姓名** | 公司名称 |
| 证书权限 | 仅 Account Holder | 仍仅 Account Holder |

**建议先走个人(Individual)**。理由:当前是验证方案可行性的阶段,个人审核快、
材料简单;组织账号的 D-U-N-S 申请本身就要好几天,且不改变「只有 Account Holder
能建证书」这条限制。日后若要以公司名义分发,可以再单独立项迁移。

唯一需要接受的代价:用户在系统提示里看到的是**个人姓名**而不是公司名。

## 2. 准备清单(学生做:先把这些备齐再开始)

| 项目 | 要求 | 备注 |
|---|---|---|
| Apple ID | 已开启**双重认证(2FA)** | 建议**新建一个专用 Apple ID**,不要用私人常用账号 |
| iPhone 或 iPad | iOS 13.1 以上 | 中国大陆注册**必须**在 Apple Developer App 里完成 |
| 设备锁 | 已设置锁屏密码 + Touch ID / Face ID | 未开启会卡在验证环节 |
| 身份证 | 账号持有人本人的 | 用于实名认证 |
| 付款方式 | 支付宝 / 微信支付 | 中国区年费约 **688 元人民币**(即 99 美元档) |
| 英文姓名与地址 | 需要填写 | 提前按拼音准备好,避免临时卡壳 |

关于「建议新建专用 Apple ID」:这个账号会长期承载公司/项目的签名身份,
和私人 iCloud 数据混在一起不利于日后交接。**新建的 Apple ID 同样需要开 2FA。**

## 3. 注册步骤

### 第一步:安装并登录(学生可协助)

在 iPhone/iPad 上安装 **Apple Developer** App(App Store 搜索),
用第 2 节准备的 Apple ID 登录。

### 第二步:发起注册(学生可协助操作,身份信息填账号持有人的)

App 内进入 **Account → Enroll**(加入),按提示:

1. 实体类型选 **Individual / Sole Proprietor(个人)**;
2. 填写真实姓名、身份证号、手机号;
3. 填写英文姓名与英文地址;
4. 阅读并同意 Apple Developer Program 许可协议。

### 第三步:实名与人脸认证(**必须账号持有人本人**)

按提示扫描身份证并进行人脸识别。**这一步不可代劳。**

### 第四步:付款(账号持有人本人)

绑定支付宝或微信支付,支付年费(约 688 元/年,**自动续订**)。

> 提醒:这是自动续订的订阅。若日后决定不再续,需要主动取消,
> 否则会自动扣款。请把续费日期记入日程。

### 第五步:等待审核

个人账号通常 24–48 小时通过,结果发到 Apple ID 邮箱。
超过 5 个工作日没动静,通过 [Apple Developer 联系页面](https://developer.apple.com/contact/) 催办。

## 4. 审核通过后要产出的东西(学生做,这是真正的交付物)

注册通过本身不产生任何可用的东西。**必须完成下面这一步,这件事才算做完。**

在一台 Mac 上操作:

### 4.1 生成 CSR(证书签名请求)

打开「钥匙串访问」(Keychain Access) → 菜单栏「钥匙串访问」→
「证书助理」→「从证书颁发机构请求证书」:

- 用户电子邮件地址:账号持有人的 Apple ID 邮箱
- 常用名称:随意可辨识即可,例如 `DSH GUI Developer ID`
- 请求是:勾选**存储到磁盘**

保存得到 `CertificateSigningRequest.certSigningRequest`。

> **关键**:这一步会在这台 Mac 的钥匙串里生成一把**私钥**。
> 私钥丢了,证书就作废,只能重新申请。所以这一步在哪台机器做,
> 后续的导出就必须在哪台机器做。

### 4.2 创建 Developer ID Application 证书

用**账号持有人**的 Apple ID 登录 [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/certificates/list),
新建证书,类型选 **Developer ID Application**,上传上一步的 CSR,
下载得到 `.cer` 文件,双击导入钥匙串。

> 每个账号最多可创建 5 张 Developer ID Application 证书,不要反复试错浪费额度。
> 若该操作提示无权限,说明当前登录的不是 Account Holder——回看 §1。

### 4.3 导出 .p12(含私钥)

钥匙串访问 →「我的证书」分类 → 找到 `Developer ID Application: <姓名> (<TeamID>)`
→ 右键**导出** → 存为 `.p12` 格式 → **设置一个导出密码并记下来**。

导出时必须能看到证书左侧有展开箭头(说明私钥在),否则导出的是无私钥的证书,不可用。

### 4.4 生成公证用的 App 专用密码

访问 [account.apple.com](https://account.apple.com) → 登录 → 「登录与安全」→
「App 专用密码」→ 生成一个,命名为 `notarization`,**记下生成的密码**
(只显示一次)。

> 说明:公证凭据有两种,App 专用密码与 App Store Connect API Key。
> Apple 推荐后者用于 CI,但前者更简单且个人账号一定可用。
> 先交 App 专用密码即可,CI 迁移到 API Key 由我们后续处理。

## 5. 交回清单(把这五样交给我)

| 交付物 | 形式 | 敏感度 |
|---|---|---|
| Team ID | 10 位字符,在开发者后台「Membership」页 | 低 |
| 证书里的开发者名称 | 形如 `Developer ID Application: Xxx Xxx (TEAMID)` | 低 |
| `.p12` 证书文件 | 文件 | **极高** |
| `.p12` 的导出密码 | 字符串 | **极高** |
| App 专用密码 + 对应 Apple ID | 字符串 | **极高** |

**安全要求(务必遵守)**:

- 后三项**不要通过微信、飞书、邮件明文发送**,也不要提交进任何 Git 仓库。
  用加密压缩包 + 另一条渠道口头告知密码,或当面拷贝。
- `.p12` 等同于「以这个身份签名的权力」。泄露意味着他人可以签发冒名的
  macOS 软件,且撤销证书会让所有已分发版本失效。
- 学生本机在交付完成后应删除 `.p12` 副本。

## 6. 常见卡点

| 现象 | 原因与处理 |
|---|---|
| Enroll 入口点不动 / 报错 | Apple ID 未开 2FA,或设备未设锁屏密码与生物识别 |
| 提示需要用 App 注册 | 中国大陆自 2019 年起要求实名,必须走 Apple Developer App,网页端不行 |
| 人脸识别反复失败 | 光线、证件反光;换环境重试,连续失败会临时锁定,等一段时间再试 |
| 审核超过一周无进展 | 通过 Apple Developer 联系页面催办,附上 Enrollment ID |
| 建证书时提示无权限 | 登录的不是 Account Holder,见 §1 |
| 导出 .p12 时没有私钥 | CSR 是在另一台 Mac 上生成的;回到那台机器导出,或重新走 4.1 |
